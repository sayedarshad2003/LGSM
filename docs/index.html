Workflow Guide: Getting Started with LGMS

Follow the operational workflow from initial prerequisites and multi-account linking to AI-powered commits and 1-click cloud repository cloning.

Step 1: Verify System Prerequisites

The standalone Windows distribution includes its own self-contained .NET 9 runtime. Ensure Git and GitHub CLI are available on your system path:

  • Git for Windows (version 2.25 or later) registered in system PATH.
  • GitHub CLI (gh) for account discovery and credential helper binding.
  • Optional: .NET 9 SDK and Microsoft SQL Server (only required when building from source).
PowerShell CLI Verification 
# Verify Git installation
git --version
# Output: git version 2.47.0.windows.1

# Verify GitHub CLI
gh --version
# Output: gh version 2.60.0 (x86_64-w64-mingw32)

Step 2: Connect Multiple GitHub Accounts

Authenticate each required GitHub account using standard OAuth browser handshakes. LGMS never inspects or logs raw access tokens:

  • Run gh auth login --hostname github.com --web for each personal or organizational profile.
  • Run gh auth setup-git to register GitHub CLI as Git's credential provider.
  • Open LGMS: all authenticated accounts populate automatically with active markers.
PowerShell Authentication Command 
# 1. Login to Primary / Personal Account
gh auth login --hostname github.com --web

# 2. Login to Enterprise / Work Account
gh auth login --hostname github.com --web

# 3. Bind Windows Credential Helper
gh auth setup-git

Step 3: Workspace Discovery & Repository Scanning

Designate a parent directory containing your code repositories. LGMS scans subfolders recursively in parallel:

  • Recursively detects valid .git repository roots.
  • Parses active branch, tracking status, and uncommitted modification metrics.
  • Double-click any repository to launch its working tree and diff workspace immediately.

Enterprise Security

Zero Token Leakage Architecture

How LGMS isolates credentials, guarantees thread-safe account switching, and preserves commit authors.

Zero Plaintext Token Storage

Traditional Git GUIs often save personal access tokens in plain text files or unencrypted SQLite databases. LGMS delegates all token storage to the secure Windows Credential Manager.

Mutex-Serialized Operations

The custom GitAccountOperationLock guarantees that account toggling and remote Git operations execute sequentially, preventing transport session collisions.

Independent Commit Identity

Switching your GitHub login for push/pull transport will never alter your local repository's user.name and user.email author configuration.
